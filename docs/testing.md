# Тесты

Тесты написаны на pytest с плагином pytest-django. Всего 36 тестов.

## Запуск

```bash
pytest
```

Полезные варианты:

```bash
pytest spots
```

```bash
pytest -k review
```

Первая команда запускает тесты только приложения `spots`, вторая — только те, в названии
которых встречается `review`.

Настройки лежат в `pytest.ini`: там указан модуль настроек Django и маска файлов с
тестами. Отдельная тестовая база создаётся и удаляется автоматически, рабочая
`db.sqlite3` не затрагивается.

## Что покрыто

| Файл | Тестов | О чём |
|---|---|---|
| `accounts/tests.py` | 6 | регистрация, несовпадение паролей, вход, выход, профиль, 404 на неизвестного пользователя |
| `spots/tests.py` | 12 | публичность списка, доступ только автора к изменению и удалению, фильтр по космодрому, отзывы, запрет второго отзыва и отзыва на свою точку, проверка диапазона оценки |
| `flights/tests.py` | 12 | подсчёт очков и граница в 30 минут, отсутствие очков до итогов, создание и блокировка прогнозов, доступ только автора, таблица лидеров, доступность публичных страниц |
| `core/tests.py` | 6 | фильтр `stars`, повторный запуск `seed_demo` |

Главное, что проверяют тесты, — права доступа: чужой пользователь получает 403 при
попытке изменить точку, отзыв или прогноз, а гость отправляется на страницу входа.

## Фикстуры

Общие фикстуры лежат в `conftest.py` в корне проекта:

| Фикстура | Что даёт |
|---|---|
| `user`, `other_user` | два пользователя, чтобы проверять права доступа |
| `spot` | точка наблюдения, автор — `user` |
| `planned_flight` | полёт через 3 дня, приём прогнозов открыт |
| `resolved_flight` | состоявшийся полёт с итогами, по нему считаются очки |

Фикстура `client` приходит из pytest-django, он же даёт доступ к базе через
`pytest.mark.django_db`.

## Как добавить тест

1. Положите функцию с именем `test_*` в `tests.py` нужного приложения.
2. Если нужна база, добавьте в начало файла `pytestmark = pytest.mark.django_db`.
3. Для запросов к страницам используйте фикстуру `client`, а для входа — `client.force_login(user)`.

Пример:

```python
def test_spot_detail_shows_title(client, spot):
    response = client.get(spot.get_absolute_url())
    assert spot.title in response.content.decode()
```

## CI

Файл `.github/workflows/tests.yml` запускает на каждый push и pull request: `manage.py check`,
проверку, что нет несозданных миграций, и сами тесты.
